**Kicking off portfolio-wide work?** `STATIC.md` carries the register conventions, the two clocks and the peer
rules; read the static core first, because it outranks everything below.

## How to read it

**Preferred — the shared skill:**

> Use the `get-mental-model` skill to read mental model `program_manager_protocol` from the bank named in `_aisdlc/config.yaml`.

**Or the CLI:**

```bash
aisdlc read -m program_manager_protocol            # prints the protocol to stdout
aisdlc read -m program_manager_protocol -o /tmp/program-protocol.md
```

## How to compose the two layers

1. Read `program-manager/STATIC.md` first — identity and hard rules. It outranks everything that follows.
2. Read the model's content (above) — the working method. This is the bulk.
3. Run on **static core + protocol**, in that order.

## If the model cannot be read

Say which happened, and do not paper over it:

- **absent** (no model by that name) → run on the static core alone and say the protocol was missing;
- **unreachable** → say the store could not be reached — a different thing from absent;
- **empty** → present with no content: treat it as absent for every purpose that reads it, and say **which**
  empty — a refresh completed and wrote nothing, or no refresh has completed. Never call it "still generating": a
  model that will never fill is not a model that is filling.

## Editing it

Replace the model's **prompt**, never its generated content:

```bash
aisdlc set-prompt -m program_manager_protocol -f <path-to-prompt.md>
```

The content regenerates from the new prompt. To refresh the protocol without changing the prompt, ask the store
for one now: `aisdlc refresh -m program_manager_protocol`.

## The portfolio register — the canonical tracking surface

- One file per portfolio, never one per project. Where it lives is this tree's own fact, so the project file
  beside `AGENTS.md` names it once; this file names no path, because a path that is right here is a path that is
  wrong in the next tree.
- Each row: project name | route (how this seat reaches that project's manager) | phase, and the document it was
  read from | when that reading was taken | the evidence condition it rests on | schedule state (ON/OFF, when,
  what it was carrying) | last tick | open-bucket count.
- The register is a **pointer**, not a copy: where it disagrees with a project's own status document, the project
  wins and the row is corrected.
- Update triggers: peer enrollment confirmed, phase lock, handoff, first deploy, close or resolve of an escalation,
  a schedule edge, or a successful read.
