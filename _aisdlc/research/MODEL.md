# research — which model to read, and how to compose

<!-- The adaptable bulk of this role's protocol lives in a mental model in the configured memory bank
     (`_aisdlc/config.yaml`). This file names it. It does not contain the protocol. -->

| | |
|---|---|
| **Bank** | the bank named in `_aisdlc/config.yaml` (fixed there, deliberately — a bank named here instead would drift between roles and silently) |
| **Model** | `research_protocol` |
| **Content** | the role's operating protocol, generated by the server from the model's prompt |
| **Prompt** | the model's `source_query` — the *improvement instruction* that regenerates the protocol |

## How to read it

**Preferred — the shared skill:**

> Use the `get-mental-model` skill to read mental model `research_protocol` from the bank named in `_aisdlc/config.yaml`.

**Or the CLI** (plain HTTP; it depends on no sibling repository — see `_aisdlc/tool/README.md`):

```bash
aisdlc read -m research_protocol            # prints the protocol to stdout
aisdlc read -m research_protocol -o /tmp/protocol.md
```

## How to compose the two layers

1. Read `research/STATIC.md` first — identity and hard rules. It outranks everything that follows.
2. Read the model's content (above) — the working method. This is the bulk.
3. Run on **static core + protocol**, in that order.

## If the model cannot be read

Say which happened, and do not paper over it:

- **absent** (no model by that name) → run on the static core alone and say the protocol was missing;
- **unreachable** → say the store could not be reached — a different thing from absent;
- **empty** (present, with no content) → treat it as absent for every purpose that reads a model, and say
  why: a refresh completed and wrote nothing, or no refresh has completed. Never call it "still generating" —
  a model that will never fill is not a model that is filling.

## Editing it

Replace the model's **prompt**, never its generated content:

```bash
aisdlc set-prompt -m research_protocol -f <path-to-prompt.md>
```

The content regenerates from the new prompt. To refresh the protocol without changing the prompt, ask the
store for one now: `aisdlc refresh -m research_protocol`.
